📊 Cardinality Breakdown

  • USER ↔ ROLE (M:N): Implemented via junction table USER_ROLES with composite primary key (user_id, role_id)
  • USER → BORROW_RECORD (1:N): One user can create multiple borrow records; user_id is foreign key in BORROW_RECORD
  • BOOK → BORROW_RECORD (1:N): One book can be borrowed multiple times; book_id is foreign key in BORROW_RECORD

⚠️ Important Notes

  • Cascade Delete: Deleting a USER or BOOK will cascade delete related records in USER_ROLES and BORROW_RECORD
  • Referential Integrity: Foreign keys enforce data consistency across all relationships
  • Junction Table: USER_ROLES enables the many-to-many relationship between USER and ROLE
  • Temporal Data: BORROW_RECORD maintains historical data even after books are returned
